# Спайк 5.3: позиции героев через Гипер Базу

Код одноразовый, после переноса выводов в `ARCHITECTURE.md` раздел 13 папка
`spike/net/` и строка `net` в `demo/demo.view.tree` удаляются.

## Итог

Задержка от `keydown` в первом окне до смены позиции чужого героя в подвале
второго окна, локальный мастер `ws://localhost:9090`, два headless Chrome с
разными профилями, три раунда подряд:

| раунд | мс |
|---|---|
| 1 | 42 |
| 2 | 47 |
| 3 | 40 |

Порог приёмки 200 мс. Из этих 40 мс до 16 мс это кадр первого окна (шаг
пишет позицию не раньше следующего `step`), до 50 мс троттлинг записи, остальное
это путь клиент → мастер → клиент и перерисовка подвала.

Ленд открытый, пресет `[[ null, rank_post( 'just' ) ]]`, ссылка
`UHhZpFrc_naf5XUWK`, лежит на локальном мастере в `<mam>/.baza/UH/`. На других
мастерах его нет.

## Как устроено

- `hero/hero.ts`: `$bog_gamengine_spike_net_hero`, словарь с `X` и `Y`
  (`atom_real`).
- `world/world.ts`: корень ленда, `Heroes: dict_to( hero )`, ключ это случайный
  id окна (`$mol_guid()`, живёт в памяти страницы).
- `self/self.ts`: `$bog_gamengine_spike_net_self` наследует героя плоского мира.
  В `step` после `super.step` сравнивает `pos` с последней отправленной, не чаще
  раза в 50 мс планирует `new $mol_after_tick( ()=> $mol_wire_async( this ).push( pawn, x, y ) )`.
  Сама запись в атомы живёт в `push`, вне мемо шага.
- `net.view.tree` + `net.view.ts`: страница `$bog_gamengine_spike_net`, одна сцена,
  свой герой на WASD, чужие герои это `Other*` спрайты с `pos <= other_pos*`,
  где `other_pos` мемо по ключу читает `X().val()` и `Y().val()`. Список чужих
  берётся из `Heroes().keys()`, отсекаются те, у кого `last_change()` старше
  15 с (мёртвые окна), сортировка по свежести.
- Подвал: `me <id> x × y | others N | <id> x × y, … | seen hh:mm:ss | pushes n | land … | master …`.
- `probe/probe.node.ts`: два Chrome, ждёт в обоих подвал, во втором ждёт id первого,
  потом три раунда: второе окно опрашивает подвал каждые 2 мс, первое жмёт `D`
  на 30 кадров, задержка это `t1 - t0` по `Date.now()` обеих страниц (одна машина).
  Без Chrome или без мастера на 9090 проба пишет строку пропуска, тест зелёный.

Мастер задаётся адресным параметром: `#!demo=net/master=localhost:9090`. Схема
дописывается сама (`http://`, yard сам меняет на `ws://`). Пин ставится в
`land_link()` до первого обращения к ленду и повторяется в `auto()`; после подмены
`yard.masters` дёргается `master_cursor( 1 )` и `( 0 )`, иначе `master_current()`
не пересчитывается (взято из `bog/max/app`).

## Грабли

1. **Две вкладки одного Chrome синкают ленд через `BroadcastChannel`**
   (`land.bus()` в `giper/baza/land/land.ts`), мастер не участвует. Замер в двух
   вкладках показал бы задержку шины, а не сети. Поэтому проба поднимает два
   Chrome с разными профилями, у них разные лорды и разные IndexedDB.
2. **У демо нет прод-мастера.** В бандле `demo/-/` нет `web.baza`, `masters()`
   без пина отдаёт origin самой страницы (`http://127.0.0.1:<порт статики>/`),
   yard стучится в него и раз в секунду пишет `Master unavailable`. Так что без
   `master=` страница вообще ни с кем не синкается. Пин в адресе обязателен.
3. **Ленд без юнитов на мастере даёт ранг 16 всем.** Первый созданный ленд
   (`8wTnHINq_N14WKwBb`) до мастера не доехал: на мастере появилась пустая папка
   `.baza/8w/`, а юнитов нет. Второе создание тем же кодом с `giper_baza_log=1`
   прошло (`Send Face → Take Face → Send Unit`, 13 юнитов). Причину первого
   провала найти не удалось, лог тогда был выключен. Признак у клиента:
   `pass_rank` 16, `total()` 0, `Heroes( 'auto' )` молча отдаёт `null`, героя
   «нет», ошибок нет.
4. **`dive( key, Type, 'auto' )` молча отдаёт `null`, пока не приехал гифт.**
   `can_change()` ложно до синка прав, поэтому регистрация героя сделана мемо
   `my_hero_ready()`, который читается в `auto()` и пересчитывается, когда права
   доедут. Регистрация в клике или в `step` потерялась бы.
5. **Первая ошибка атласа в консоли.** На странице `net` при первом кадре
   вылетает `Atlas image … is 512×512, expected 64×64, is it loaded?`, на `flat`
   этого нет. Герой при этом рисуется (пиксель центра `[240,200,140]`, как у
   `flat`). Отличие от `flat` в том, что там `hero_stat` читает `Atlas().ready()`
   раньше первого `fill`. В спайке не чинил, это про движок.
6. **Аксессор к атому без `@ $mol_mem`, чтение через мемо можно.** `other_pos`
   это мемо по ключу поверх `val()`, оно обновляется от чужих юнитов, потому что
   через него никто не пишет. Свой герой пишет только через `push`.
7. **Запись атома не копит историю.** 39 записей за 2 с (пара `X`, `Y` на
   каждую) не изменили `land.total()`: 41 юнит до и после. Перезапись атома
   переиспользует `self` предыдущего юнита. Ленд не растёт от движения, растёт
   только от новых героев (ключ в `Heroes` плюс два атома на окно, и каждый
   `$mol_guid()` при перезагрузке страницы это новый герой).
8. **`last_change()` с точностью до секунды.** `unit.time()` в секундах, для
   «время последнего обновления» в подвале хватает, для замера нет, замер снят
   опросом DOM.
9. **`X` и `Y` это два юнита.** Читатель может увидеть новый `X` со старым `Y`
   на один тик. Для спайка неважно, для игры позицию класть одним атомом
   (`atom_list` `[ x, y ]`), чтобы обновление было атомарным.
10. **Криптография и `land_grab` только в фибре.** Создание ленда сделано в мемо
    `land_link()`, там `land_grab` ретраится сам. Из консоли это не работает,
    см. гайд.

## Что записать в архитектуру, раздел 13

- Сущность на игрока: словарь `Heroes` по id окна, у каждого игрока своя ветка,
  права `post` без PoW (`just`). Чужие ветки никто не правит, конфликтов нет.
- Позиция одним атомом-списком, а не парой атомов.
- Частота записи 20 Гц (гэп 50 мс) даёт задержку 40–50 мс на локальном мастере
  и не растит ленд.
- Запись из шага откладывается на тик (`$mol_after_tick` + `$mol_wire_async`),
  как `sound.play`; в самом `step` только сравнение с последней отправленной.
- Чужие герои это холодные узлы: `@ $mol_mem_key pos( id )` над `val()`
  атомов, спрайт с `pos <= other_pos*`. Пишущий аксессор с мемо запрещён.
- Присутствие по `last_change()`: игрок, не писавший N секунд, считается
  вышедшим. Явного «отключился» в Базе нет, ленд append-only.
- Мастер выбирает приложение, не движок: пин `#!master=host:port` в entry
  приложения, до первого обращения к ленду, с перебросом `master_cursor`.
- При отключении мастера: yard сам переподключается раз в секунду
  (`Master unavailable`, код 1006), локальные записи копятся в IndexedDB и
  доезжают после реконнекта. Спайк это не мерил, только видел в логе.
- Замер сети всегда двумя браузерами с разными профилями, не вкладками:
  вкладки одного origin синкаются по `BroadcastChannel` мимо мастера.
