## Этап 0. Спайки

Три проверки фундамента. Шли параллельно. Все три приняты 22.09.2026, находки
перенесены в архитектуру (разделы 1, 3.1, 3.1а, 3.7, 5, 7, 8, 14) и в STYLE.md. Папка
`spike/` удалена после приёмки задачи 1.9, отчёты остались в истории репозитория.
Образцы теперь живые модули: шейдер в TS это `shader/flat`, владелец GL это `draw`,
проба пикселя это `probe`.

- [x] **S1. Две программы с разными face в одном бандле. ПРИНЯТ.** Грабля шире, чем
  думали: падают обе программы, порядок не важен. Обход работает только с
  `$mol_3d_glsl_both` в префиксе. Вторая грабля: подчёркивание в `.glsl` сборщик читает
  как путь модуля. Отчёт спайка S1 в истории репозитория, коммит 2ad4921.

- [x] **S2. Десять тысяч инстансов при 60 кадрах. ПРИНЯТ.** Горячий буфер: 0.6 мс на
  10 000, 14 мс на 500 000, ломается на миллионе. Реактивный контроль: 14 мс уже на
  10 000, 153 мс на 50 000. Цена записи в атом около 1.3 мкс, аллокация ни при чём.
  Замер внутри `paint()` занижает кадр втрое, потому что `step` считает планировщик.
  Отчёт спайка S2 в истории репозитория, коммит 9643ddc.

- [x] **S3. WebGL в headless Chrome через `bog/probe`. ПРИНЯТ.** Со штатным
  `--disable-gpu` контекста нет, с `--use-angle=swiftshader` центр красный. В пробу
  добавлено поле `flags` (коммит `6b3c091` в `b-on-g/probe`). Нужны
  `preserveDrawingBuffer: true` и `ready` по `canvas.width > 0`. Прогон 0.7 с. Отчёт
  спайка S3 в истории репозитория, коммит 84a7f24, живой образец `probe/probe.node.ts`.

## Этап 1. Каркас

Цель: вращающийся цветной квад на экране, камера переключается между плоской и
объёмной, всё реактивно. Ни одной картинки.

- [x] **1.1. `clock`.** `frame()`, `dt()`, `time()`, `paused?`, `speed?`. `dt` режется
  сверху 0.1 с. **Приёмка:** тест в ноде с подменой `$mol_state_time.now`: три тика
  дают `frame 3`, пауза даёт `dt 0`, скачок времени на 5 с даёт `dt 0.1`.

- [x] **1.2. `vec`.** `vec2`/`vec3` как функции над `Float32Array` с выходным
  аргументом: `add( out, a, b )`, `scale`, `len`, `norm`, `dot`, `cross`, `lerp`.
  **Приёмка:** тест на каждую функцию, ни одной аллокации внутри (проверить глазами,
  в тесте `out === result`).

- [x] **1.3. `node`.** `pos?`, `rot?`, `scale?`, `parent?`, `trans()` из них,
  `world()` через родителя, `step( dt )` пустой, `kids()`. Поворот в плоском
  режиме это угол вокруг Z, в объёмном три угла; храним всегда три.
  **Приёмка:** тест: ребёнок со сдвигом 1 у родителя с поворотом π/2 даёт `world`
  с переносом `(0, 1, 0)` с точностью 1e-6.

- [x] **1.4. `cam`, `cam/flat`, `cam/deep`.** `view()` это инверсия `world()`.
  `flat.proj( aspect )` ортография по `zoom` и `pixels_per_unit`, `deep.proj( aspect )`
  перспектива по `fov`, `near`, `far`. **Приёмка:** тесты по разделу 14 архитектуры:
  точки на границах переходят в `±1`.

- [x] **1.5. `shader` и `shader/flat`.** База собирает программу из `face`, `vert`,
  `frag` с подмешиванием только `$mol_3d_glsl_both` (образец `shader/flat/flat.ts`).
  Первый шейдер: цветной квад без текстуры, `inst_trans`, `inst_tint`.
  **Приёмка:** тест в ноде: `vert()` и `frag()` содержат `main`, каждое имя из
  `face.input` встречается в `vert()`, `program()` не содержит `$mol_3d_glsl_vert`.

- [x] **1.6. `shape`, `shape/quad`.** База добавляет к `$mol_3d_shape` `normals()` и
  `count()`. Квад как `TRIANGLE_STRIP` из четырёх вершин, обход против часовой, чтобы
  cull не срезал. **Приёмка:** тест на длины массивов и порядок обхода.

- [x] **1.7. `batch`.** `shader`, `shape`, `nodes()`, плоские буферы `trans`
  (`16 × cap`), `tint` (`4 × cap`), `fill()` пишет `world()` каждого узла на место
  и возвращает `count`. Рост `cap` удвоением, буферы пересоздаются только при росте.
  **Приёмка:** тест: два узла дают `count 2` и правильные переносы в `trans` по
  смещениям 12 и 28; третий узел не аллоцирует, если `cap` хватает.

- [x] **1.8. `scene`.** Корневой `node`, `nodes()` обходом, `batches()`, `step()`
  мемо на `clock.frame()`: шаги 2–4 раздела 5 архитектуры. **Приёмка:** тест: узел с
  `step`, двигающим `pos` на `dt`, через три тика на `dt 0.016` сдвинут на 0.048.

- [x] **1.9. `draw`.** Наследник `$mol_3d_pane`, контекст с
  `preserveDrawingBuffer: true`. Кэш программ по шейдеру, VAO и буферов по батчу,
  `paint()` по разделу 7, `stat()` по разделу 5. Состояние GL перед каждым батчем
  выставляется явно. **Приёмка:** проба по рецепту раздела 14 (образец
  `probe/probe.node.ts`): квад с `inst_tint` красный, центр холста красный. Второй кадр не
  зовёт `createBuffer` (обернуть контекст прокси в пробе и посчитать). После приёмки
  папка `spike/` удаляется тем же коммитом.

- [x] **1.10. `demo`, первая страница.** Корень `$mol_book2` с одной страницей «Квад»:
  панель `draw` внутри `sub`, никогда не корнем (3.7). Сцена из `scene`, узел,
  вращающийся в `step`, переключатель камер `$mol_switch`, чекбокс паузы к
  `clock.paused?`, `draw.stat()` в подвале. Единственный `index.html` пака.
  **Приёмка:** пользователь открывает через дев-сервер, квад крутится, пауза
  останавливает, камера переключается без перезагрузки. `git ls-files | grep -c index.html` равно 1.

## Этап 6. Хвосты после переноса аркады

Перенос `bog/game/arcade` (задача 3.6, коммит `355ec89` в `b-on-g/game`) показал, чего
движку не хватает. Аркада живёт без этого, но каждый пункт это дыра в API.

- [x] **6.1. Билборд. ПРИНЯТ 24.09.2026.** Флаг `billboard?` переехал с текста и частиц
  в `node`: `trans()` берёт рыскание камеры сцены (`atan2` по третьей колонке её
  `world()`), у спрайта и меша флаг появился в `props()`. Аркада вместо `rot <= cam_rot`
  ставит `billboard true` и биндит камеру сцене (`cam <= Cam`), без этого узел камеры не
  видит.

- [x] **6.2. Режим линий.** `shape.mode()` получает `'lines'`, `draw` рисует `LINES`
  поверх батча при `wireframe?` панели. Возвращает чекбокс wireframe в аркаду и
  «Комнату». **Приёмка:** проба: с wireframe пиксель на ребре ящика белый.

- [x] **6.3. Туман. ПРИНЯТ 24.09.2026.** Юниформы `fog` (`vec2`) и `fog_color` (`vec3`)
  в `shader/solid` и его `plain`, затухание к цвету по расстоянию от камеры, ноль в конце
  значит «нет». Свойства `fog?` и `fog_color?` у панели, `fog_color` по умолчанию берёт
  цвет очистки. Чекбокс «Туман» в комнате, проба: дальняя стена темнеет на 59 единиц
  суммы, ближний пол на 4.

- [x] **6.4. Тайлинг плоскости по осям. ПРИНЯТ 24.09.2026.** `shape/plane.tile` это
  пара `(u, v)` `Float32Array`. Потребители (комната, «Ящики», аркада, шутер) считают
  пару по размерам карты, пол больше не растянут по глубине. Литералом из дерева пара не
  задаётся: список чисел ломает тип переопределения, нужен биндинг на метод.



- [x] **6.5 и 6.7. Тихая загрузка. ПРИНЯТ 24.09.2026.** `atlas.ready()` ложь, пока в
  слоях есть заглушка, `draw` читает только его и не бросает из `paint`.

# Движок общего назначения

Этапы 0–6 дают библиотеку для игр внутри приложений на $mol. Кирилл (23.09.2026):
нужен редактор и настоящая 3D-физика, цель это движок общего назначения. Ниже что
для этого не хватает, в порядке, в котором это имеет смысл делать. Размер каждой
задачи в днях одного молера с приёмкой, честно и с запасом.

Сейчас в движке 4 700 строк TS в 71 файле. Общее назначение это ещё примерно
25–30 тысяч строк, то есть 4–6 месяцев потоком из трёх-четырёх молеров. Это меньше,
чем «несколько месяцев с лютым геморроем» за счёт того, что UI, сборка, тесты,
синк и редактор `view.tree` уже есть в $mol, а не потому что задача маленькая.

## Этап 7. Редактор

Ставка та же, что у `bog/vmap`: сцена это `view.tree`, редактор правит исходник.
Редактор живёт отдельным паком `bog/gamestudio`, движок о нём не знает. Рабочее
имя, односложное.

- [x] **7.1. Инспектор узла. ПРИНЯТ 23.09.2026.** `bog/gamestudio/app`: три
  неподвижные `$mol_page`, дерево `$mol_list` по `scene.nodes()`, инспектор `$mol_form`
  с `$mol_number`, `$mol_select` по слоям атласа, чекбоксом; сцена-образец в
  `sample/`. Проба: колонки в ряд, холст рисует, клик показывает свойства. Коммит
  `c45b1f8` локально, репозиторий `b-on-g/gamestudio` ещё не создан. Грабля
  дев-сервера: `deploy` и `index.html` копируются в `-/` только по прямому запросу
  пути.
- [x] **7.2. Выбор мышью и гизмо. ПРИНЯТ 23.09.2026.** Клик через `point.pick`
  выбирает узел, стрелки X и Y и квадрат в батче поверх сцены (`doc.overlay`),
  размер постоянный на экране, перетаскивание пишет в узел каждый кадр и в документ
  один раз на `pointerup`. Проба: стрелка сдвинула монету на 80 px, ось держит, `y`
  не тронут. Хвосты: поворот и масштаб, перенос у узла с повёрнутым родителем,
  `pointercancel`, толщина линий 1 px. Коммит `2e8a415` локально.
- [x] **7.3. Сохранение в `view.tree`. ПРИНЯТ 23.09.2026.** `bog/gamestudio/doc`:
  `source` это текст `view.tree`, `set( узел, свойство, значение )` правит ровно одну
  строку, свой дамп по `span.row` (штатный `toString()` схлопывает списки из одного
  элемента), сцена интерпретируется из дерева через `props()` с мемо по тексту
  объявления. Четвёртая колонка «Исходник» с `$mol_textarea`. Проба: правка текста
  перекрашивает героя, правка в инспекторе даёт `pos / 5 0 0` без других изменений.
  Коммиты `29c298f`, `57ea9b5` локально.
- [x] **7.3а. Компиляция вместо интерпретации. ПРИНЯТ 23.09.2026.** Движок принимает
  `ArrayLike` в векторах, `kids?`, `tint` у узла (коммит `783ea4e`). Редактор компилирует
  документ штатной цепочкой `$mol_view_tree2_to_text` и `new Function`: 0.3 мс на сборку
  класса, бандл редактора +71 КБ, `unsafe-eval` в README. Диалект: `pos / 1 2 0` в одну
  строку раскладывается из цепочки в элементы перед компиляцией, литералы свойств узлов
  переписываются в `prop? <=> Node_prop?`, чтобы гизмо писал в узел штатно. Часы вне

## Этап 10. Игровые системы

- [x] **10.1. Префабы. ПРИНЯТ 25.09.2026.** Узел-шаблон в `view.tree`, инстансы с
  переопределением свойств. Движку не понадобилось ни строки, вся работа вышла в
  редакторе: четыре поломки адресации плюс две, найденные по дороге (`chain( name )`
  собирает свойства по цепочке баз, `own( klass, line )` решает, своя ли строка, иначе
  правка чужой строки молча терялась). Инспектор подписывает «часть префаба, затронет N»,
  кнопка «Переопределить в этом инстансе» заводит верхнеуровневое объявление и меняет
  строку на ссылку. Запрещённая вложенная форма проверена дословно: даёт
  `Unexpected token 'const'`, тест ловит это и по структуре, и по компиляции.
  Сама кнопка завела дыру, которую пришлось закрывать тем же коммитом: `refs` не видел
  строку-подмену, поэтому после переопределения инспектор продолжал адресовать общее тело
  префаба, то есть действие чинило документ и тут же ломало адресацию.
  **Долг на будущее.** Подпись считает по имени объявления, а не по свойству: в нынешней
  модели «своё значение» и «своё объявление» — одно и то же, ветка по свойству оказалась
  недостижимой и выкинута вместе с параметром. Настоящей она станет при правке тела
  префаба напрямую, куда инспектор пока не попадает (`nodes()` перечисляет только
  развёрнутые инстансы). Тот, кто заведёт выбор префаба, обязан вернуть вторую ветку
  вместе с тестом, который на ней падает.
  Движковая половина закрыта 25.09 **без единой строки кода.** Модуль `prefab` был
  написан (шаблон-объект, ячейка на свойство на инстанс, клонирование детей) и удалён
  коммитом `324a81d`: наследование классов даёт то же самое статически и дешевле,
  `new $my_guard` закрывает и спавн в рантайме, а живая правка шаблона без пересборки
  нужна только при запущенной сцене, где это правка правил игры на ходу.
  **Заложенная мина в выбранной форме документа.** Префаб это второе верхнеуровневое
  объявление в том же файле, а класс теряет рукописное тело базы, если база объявлена
  в том же `.view.tree`: топосорт кладёт сгенерированный `.js` перед `.view.ts`, и
  гранулярность там файловая, а не классовая. Сейчас не стреляет, потому что редактор
  компилирует документ в рантайме и рукописного тела нет вовсе. Выстрелит в день, когда
  документ с префабом соберут статическим модулем.
  Разведка 25.09 на живом бандле: **движку править нечего, префабы уже работают.**
  Два инстанса одного класса развернулись со своими под-узлами, переопределённые
  свойства компилируются в отдельные мемо на инстанс, запись в один не задевает другой.
  Вся работа в редакторе, и там четыре поломки, все воспроизведены: корень документа
  кладётся под пустым ключом для каждого верхнеуровневого объявления и побеждает
  последнее (то есть корнем становится база префаба); из-за этого обход документа
  возвращает узел из тела префаба вместо инстансов сцены; сбор ссылок берёт `kids /`
  только из собственного тела, а у инстанса его нет; `unlock` не трогает верхнеуровневые
  классы, поэтому запись унаследованного свойства глотается молча.
  **Принятые решения по интерфейсу.** Префаб — второе верхнеуровневое объявление в том
  же файле документа, отдельный модуль отпадает: редактор обязан видеть унаследованное
  тело как дерево. Новых базовых классов нет, префаб это любой узловой класс. `props()`
  движок не расширяет: в рантайме разницы между унаследованным и переопределённым
  свойством нет, признак происхождения считает редактор по дереву.
  **Общий под-узел.** Правка свойства под-узла инстанса по умолчанию пишется в тело
  префаба, инспектор подписывает «часть префаба, затронет N инстансов». Переопределение

## Этап 15. Уроки игры, сделанной через редактор

Игра `bog/crumb` (локально, без удалённого репозитория) собрана мышью в редакторе и дописана
руками. Из документа редактора в игру переехали девять строк карты и шесть пар координат,
руками написано 468 строк. Список ниже — очередь по важности, а не по порядку находки.

- [x] **15.1. Документ редактора должен собираться в MAM. ПРИНЯТ 25.09.2026.** Самое важное, без этого пути от
  редактора к игре не существует вовсе. Редактор пишет позицию списком (`pos / 10.5 -1.5 0`),
  а такой файл падает на аудите: `TS2344, Type 'readonly any[]' does not satisfy the constraint
  'Float32Array'`. То есть редактор нарушает собственное правило пака про вектор из дерева
  (STYLE.md, «Вектор из дерева»), и не замечает этого, потому что компилирует документ в
  браузере через `new Function` без проверки типов. Каждый поставленный мышью узел приходится
  переписывать руками.
  **Приёмка не «`pos` стал биндингом», а тест, который берёт документ, выданный редактором, и
  прогоняет по нему сборку.** Иначе правка отвалится молча при первом же новом свойстве.
  **Очевидная правка хуже нынешней поломки, проверено 25.09.2026 сборкой и рантаймом.** Если
  писать `pos <= Hero_pos Float32Array`, как велит правило пака, аудит становится зелёным, а
  сгенерированный код отдаёт `new Float32Array()` — буфер НУЛЕВОЙ длины. Тип сходится, значение
  выброшено, все узлы встают в никуда. Сейчас документ хотя бы громко не собирается.
  Причина: чистый `view.tree` не умеет выразить литерал `Float32Array` вовсе. Все игры пака
  пишут `<= что-то Float32Array` в дереве, а значение отдают методом в `.view.ts`; у документа
  редактора спутника на TS нет, поэтому он и жил только в браузере, где типов нет.
  **Решение: редактор экспортирует модуль из двух файлов** — дерево плюс спутник с
  методами-векторами. Не «минус», а признание: сцена и есть модуль, а не сниппет, и все четыре
  игры устроены именно так.
  **Вариант «база сама переведёт список в буфер» невозможен, а не дорог.** Литерал в дереве
  вешает на экземпляр собственную функцию, и базовый аксессор не выполняется вообще (раздел 14
  архитектуры). Остаточная форма «преобразует потребитель» отпадает по цене: потребитель `pos()`
  это горячий путь, чтение на узел за кадр, и за безусловную работу на каждом узле мы уже
  получили двукратную регрессию кадра (15.12).
  Сделано: `doc.module( klass )` отдаёт пару текстов — дерево, где каждый числовой список стал
  типизированным портом, и спутник на TS с самими числами. Правило выбора «числовой список»,
  поэтому строковые списки и ссылки на детей экспорт не трогает. Покрытие шире `pos`: в фикстуре
  лежат `pos`, `tint` и `scale`, потому что инспектор пишет их одним и тем же методом и болезнь
  была общая.
  **Приёмка устроена лучше, чем я просил.** В паке появился модуль `case/`: там лежит документ,
  выданный редактором, и рядом он же, вывезенный экспортом, **настоящими файлами** — значит их
  типы проверяет сама сборка пака, а не тест. Тест сверяет вывод экспорта с этими файлами. Новое
  векторное свойство, которое экспорт не умеет, краснеет дважды: сперва тестом на расхождении,
  потом аудитом на типах. Прогон TypeScript из теста отвергнут сознательно и вслух: `require`
  пакета втащил бы десятки мегабайт в тестовый бандл на каждый прогон.
- [x] **15.1а. Кнопка вывоза сцены модулем. ПРИНЯТ 25.09.2026.** На странице «Исходник» поле
  имени класса и две ссылки, «Вывезти дерево» и «Вывезти спутник»; имена файлов по последнему слову
  класса, по умолчанию корневой класс документа. Плохое имя **гасит ссылки, а не роняет страницу**:
  наверх пропускается только приостановка. Тест сверяет содержимое ссылок с выводом экспорта, а не
  форму строки.
  **Найдена ловушка в существующей кнопке:** «Скачать файлом» отдаёт документ, который как раз и не
  собирается, то есть пользователь мог воспроизвести исходную болезнь своими руками. Решено

- [ ] **15.3. Удаления, переименования и дублирования нет нигде.** Ни в дереве, ни в
  инспекторе, ни по клавише. Поставленный по ошибке узел убирается только правкой текста.
  Имя не редактируется потому, что `name` не входит в `props()` узла движка, и из-за этого пять
  поставленных крошек называются одинаково, а выбирать нужную приходится перебором.
  **Решение по имени: движок не трогаем.** `node.name()` уже есть, документ уже умеет строку
  `name \Крошка`, `doc.node()` уже предпочитает имя из документа имени класса, а `doc.set`
  уже генерирует такую строку. Не хватает единственного — поля в форме инспектора, потому что
